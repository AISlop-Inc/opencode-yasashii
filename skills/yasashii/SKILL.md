# やさしい日本語版の併産

レポートのHTMLを受け取り、本文だけをやさしい日本語にした版を隣に作る。
原文は書き換えない。読む人によって使い分けられる状態で納品する。

## 初回セットアップ

```bash
bash ~/.config/opencode/skills/yasashii/setup.sh
```

モデル（423MB〜）は初回実行時に自動でダウンロードされる。

## 使い方

```bash
~/.config/opencode/skills/yasashii/bin/yasashii report.html
# → report.yasashii.html
```

| オプション | 用途 |
|---|---|
| `--model 0.8b` | 既定。9,800字のレポートで約40秒 |
| `--model 2b` | 用語が残り、戻しが減る。同じレポートで約4分 |
| `--model 8b` | さらに品質優先。6GB、同じレポートで10分超の見込み |
| `--glossary terms.json` | 専門用語の置き換えを指定 |
| `--out path.html` | 出力先を変える |
| `--limit N` | 先頭N件だけ変換して品質を確認 |
| `--dry-run` | 対象件数と文字数だけ表示 |

## 仕組み

- HTMLのテキストノードだけを、文単位（250文字程度）で変換する。
- `<code>` `<pre>` `<script>` `<style>` `<svg>` と属性値は触らない。
- インライン要素に分断された短い断片や、助詞から始まる続きの文は変換しない（文脈がなく誤変換するため）。
- 数字・コード識別子・バッククォート内の文字列が消えた文は、自動で原文に戻す。
- 変換後に長さが0.5〜2.2倍を外れた文、日本語が英語に化けた文、原文にない英単語が出た文も原文に戻す。
- 15文字以下の見出しが勝手に文（です・ます調）になった場合も戻す。
- 戻した件数と理由、置換位置を特定できなかった件数は実行結果のJSONに出る。

## レポート納品時の手順

1. レポートのHTMLを書き終える。
2. `yasashii <report>.html` を実行する。
3. 元のHTMLと `.yasashii.html` の両方のパスを報告する。
4. 表・グラフ・リンク・数値が崩れていないか目視で確認する（自動検証は文単位のみ）。

## 用語を置き換える

専門用語が残って不自然な場合は用語集を渡す。変換の質が最も大きく変わるのはここ。

```json
[
  {"source": "オーバーヘッド", "target": "余分にかかる時間"},
  {"source": "レイテンシ", "target": "応答時間"},
  {"source": "埋め込みベクトル", "target": "意味を数値にしたデータ"}
]
```

```bash
yasashii report.html --glossary terms.json --model 2b
```

## 注意

- 0.8Bは「少しやさしい」まで。漢語とカタカナ語はかなり残る。
- 見出しは変換されないことがある（名詞句のため）。
- 意味がわずかにズレる文がある（例: 埋め込み→埋め込まれた）。数値と固有名詞は自動検証するが、本文の意味は目視で確認する。
