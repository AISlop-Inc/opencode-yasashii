# 文章共通のやさしい日本語仕上げ

HTMLだけでなく、人に読ませる最終的な日本語の文章に使う。
チャット回答、説明、メール案、Markdown、テキスト、HTML、文書やスライドに入れる本文が対象。
生成中のコード、ログ、機械が読む設定・JSON、厳密な原文引用は対象にしない。
ファイルは原文を残して別名で保存する。
チャットや新しい文書は、仕上げた文章を最終出力に使い、毎回二つの版を表示しない。

## 成果物の形式を問わない手順

1. 事実・条件・数値がそろった文章を作る。
2. 通常の文章は標準入力へ、チャットの下書きはMarkdownとしてCLIへ渡す。
3. 原文と候補を比べ、主語・否定・条件・確定／未確認が変わった部分は採用しない。
   説明が利用者への指示に変わっていないか、処理の共通化を文章の形式統一と誤読していないかも確認する。
   不自然な助詞や重複が残る場合も、そのまま提出しない。原文を残すか、意味を保って編集する。
4. 確認できた文章を最終回答にするか、文書・スライドなどの作成ツールへ渡す。

**変換しなかった箇所も、読みやすさの確認を省略しない。**
見出し、カードのラベル、表の項目名、図の説明なども対象。
`unconverted_labels` に出た文章を原文・周囲の説明と照合し、意味が分かりにくければ自分で直す。
「追加千環境」のように言葉を詰めるのではなく、何を何回測った値かを説明する。
漢数字の「千」を「1,000」へ直す場合も、周囲の件数・単位と同じ意味か確認する。
数値やタグの一致だけで、文章全体を読みやすく直したと報告しない。

### 見出し・ラベルもやさしい日本語にする

`unconverted_labels` は、確認を促すだけで終わらせず、仕上げる対象として扱う。
短い見出しをそのままモデルへ渡すと、必要な説明が増えないことや、対象・単位を取り違えることがある。
次の手順を、スキルを使うエージェントが行う。
CLIが文書の周囲を読んで自動で行う処理ではない。

1. 見出しと周囲の本文・表を読み、対象・動作・回数・指標を確認する。
   見出しだけで分からない事実を推測で足さない。
2. 確認できた意味を、句点で終わる短い説明文にする。
   何の平均か、何を追加したのかを省かない。
   漢数字を算用数字にする場合は同じ値か確認する。
   測定環境の数を測定回数で言い換えるのは、各環境で1回ずつ測ったと確認できた場合だけ。
3. その説明文を標準入力から `yasashii` に渡す。
   元の見出し・周囲の根拠・説明文・変換候補を照合し、対象や単位が変わった候補は採用しない。
   自動検査で戻された場合は、確認済みの説明文を使う。
4. 意味が残る範囲で「です」「でした」などを省き、見出しやラベルへ戻す。
   元のタグ、リンク先、ID、数値表は変えない。
   短くすると分かりにくくなる場合は、説明文のまま使う。
5. 最終的な見出しを、周囲の本文と表示画面でも確認する。
   根拠が足りない箇所は原文を残し、未確認として伝える。

例として、周囲の本文で「新しい1,000環境で、各1回の起動時間を測った平均」と確認できた場合は、
「追加千環境でも3.25秒」を次の説明文にしてから変換する。

```bash
printf '追加で1,000回測ったときの起動時間は平均3.25秒でした。' | yasashii
```

見出しは「追加で1,000回測った起動時間は、平均3.25秒」のように仕上げる。
元の「千環境」を直接渡して「1000秒」とされた実例があるため、モデル任せで単位を補わせない。

変換モデルに構成・内容の追加調査をさせない。
CLIの検査は意味全体を保証しないため、候補をそのまま無条件に提出しない。
変更を採用した出力は `review_required: true` として返す。
これは「モデルが承認した」という意味ではなく、最終出力に使う前の原文照合が必要という印。
30例の調査と追加12例の確認でも、候補の意味の変化や不自然な日本語が残った。
文書全体を無条件に書き換える品質と判断しない。
ユーザーが原文のまま、厳密な引用、特定の文体を指定した箇所は優先して守る。
変換できない場合は元の文章を残し、モデルを使ったと偽らない。

## 初回セットアップ

```bash
bash ~/.config/opencode/skills/yasashii/setup.sh
```

モデル（423MB〜）は初回実行時に自動でダウンロードされる。

## 使い方

```bash
~/.config/opencode/skills/yasashii/bin/yasashii report.html
# → report.yasashii.html
yasashii notes.md            # → notes.yasashii.md
yasashii message.txt         # → message.yasashii.txt
printf '当該機能を無効化する必要があります。' | yasashii
cat draft.md | yasashii --format markdown
# 標準入力では変換した文章がstdout、検査結果がstderrへ出る。
yasashii draft.md --stdout
```

| オプション | 用途 |
|---|---|
| `--model 0.8b` | 既定。速いが、難しい用語は残りやすい |
| `--model 2b` | 比較用。大きくしても誤訳が減るとは限らない |
| `--model 8b` | 未評価。大きいモデルでも正確さは保証されない |
| `--glossary terms.json` | 専門用語の置き換えを指定 |
| `--context background.txt` | 用語や背景の参照文。既定では付けない |
| `--format text/markdown/html` | 入力形式を指定。ファイルは拡張子で自動判定 |
| `--stdout` | ファイルから変換した文章を標準出力へ返す |
| `--out path` | 出力先を変える |
| `--limit N` | 先頭N件だけ変換して品質を確認 |
| `--dry-run` | 対象件数・文字数と、確認が必要な見出し・ラベルを表示 |

## 仕組み

- 公式の出力言語コード `ja-easy` と入力言語 `ja` を明示し、温度0で生成する。
- 文章を選ぶ部分だけ形式ごとに分け、言い換え・検査・原文への復帰は共通処理を使う。
- MarkdownはCommonMark解析でコード・リンク・強調・引用・HTMLを含む段落を保護する。表やYAMLヘッダーもそのまま残す。
- 書式を壊さないため、複雑な段落は無理に部分変換しない。文章だけを形式に組み込む前に渡すと変換範囲を広げられる。
- 拡張子が未知のファイルを勝手に文章扱いしない。PDF・Word・PowerPointなどは直接読み書きせず、作成ツールへ渡す前の本文に使う。
- HTMLのソース位置でテキストだけを置換する。同じ文が属性やスクリプトにあっても検索置換しない。
- `<a>` `<code>` `<pre>` `<script>` `<style>` `<svg>` と属性値は触らない。
- 句点で終わらない見出しや断片、助詞から始まる続き、URL・パス・バッククォートを含むノードは残す。
- 数値は出現順も保持し、比較の向きや対応値の入れ替わりを拒否する。コード識別子の消失も拒否する。
- 変換後に長さが0.5〜2.2倍を外れた文、日本語が英語に化けた文、原文にない英単語が出た文も原文に戻す。
- 15文字以下の見出しが勝手に文（です・ます調）になった場合も戻す。
- 数値の追加も許可しない。単位が変わった文、文末が途中で切れた出力も戻す。
- 年月・英字単位も確認する。複雑な否定、指示文の追加、仕上げ処理の意味の消失を疑う候補は戻す。
- HTMLは子タグ・文字参照で分かれた要素を丸ごと保護し、引用も変換しない。折り返された文の後半だけを変換しない。
- 大文字で始まる英語の名前も保持する。「除外・削除・出力を落とす」が取得へ反転した疑いのある文は原文に戻す。
- 戻した件数と理由、置換位置を特定できなかった件数は実行結果のJSONに出る。

## レポート納品時の手順

1. レポートのHTMLを書き終える。
2. `yasashii <report>.html` を実行する。
3. 元のHTMLと `.yasashii.html` の両方のパスを報告する。
4. 表・グラフ・リンク・数値が崩れていないか目視で確認する（自動検証は文単位のみ）。
5. 見出し・カード・表の項目名まで読んで、測定の対象・回数・指標が伝わるか確認する。
   変換対象外の文章を確認せずに残した場合は、全体の仕上げが終わったとしない。

## 用語を置き換える

専門用語が残って不自然な場合は用語集を渡す。変換の質が最も大きく変わるのはここ。

```json
[
  {"source": "オーバーヘッド", "target": "余分にかかる時間"},
  {"source": "レイテンシ", "target": "応答時間"},
  {"source": "埋め込みベクトル", "target": "意味を数値にしたデータ"}
]
```

```bash
yasashii report.html --glossary terms.json --model 2b
```

## 注意

- 0.8Bは「少しやさしい」まで。漢語とカタカナ語はかなり残る。
- 用語集は文脈に合う語だけを選んで明示的に渡す。背景説明と併用しても改善するとは限らない。
- 見出しは変換されないことがある（名詞句のため）。
- 数字や一部のコード識別子の検証は意味の検証ではない。主語・否定・条件・未確認の扱いは原文と目視で照合する。
